# Reproducing the CBIO7215 dependency-confounder study

Prepared 2026-10-11. Everything below distinguishes **ORIGINAL** artifacts (produced 2026-10-01 by
the runs that generated the reported numbers) from **VERIFICATION** artifacts (produced 2026-10-11
only to check the originals). No reported number came from a verification run.

---

## 1. Provenance statement

**Every score in the report and slides came from code that was actually executed on real DepMap
data.** Nothing was simulated, estimated or typed in by hand.

- 2026-10-01: six files were downloaded from the DepMap portal through the user's Chrome
  (1.39 GB), parsed on the user's Mac, and the derived matrices in `data/` were copied to the
  analysis machine.
- 2026-10-01 12:59–16:07 (UTC+04:00): the main experiment and all ablations were run on those
  matrices; logs are in `logs/`, per-gene outputs in `results/`.
- The report, figures and slides are generated by scripts that read `results/`, and
  `src/check_consistency.py` re-derives every quoted number from those files (84/84 pass).

Verification performed 2026-10-11 (section 7): the preprocessing was rerun from the raw downloads
and reproduced all six derived files **byte-for-byte**; a 40-gene model rerun reproduced the
original per-gene R² and Spearman values **exactly** (max difference 0.0).

## 5. Software

Two environments were involved, recorded honestly:

- **Preprocessing** (user's Mac, Linux VM inside the Claude desktop app): Python 3.10.12,
  numpy 2.2.6, pandas 2.3.3. Scripts as actually run on 2026-10-01 are in
  `provenance/original_vm_scripts/` with their original log.
- **Modelling, analysis, figures, slides** (cloud container, 2 CPU cores, 7 GB RAM): Python
  3.11.15, numpy 2.4.4, pandas 3.0.2, scipy 1.17.1, scikit-learn 1.8.0, matplotlib 3.10.9,
  python-pptx 1.0.2. See `results/environment.json`. No GPU.

`src/prep/prep.py` and `src/prep/build.py` are cleaned copies of the originals. The only changes
are docstrings, whitespace, and folding the PatientID merge (originally a separate inline step)
into `build.py`. The byte-identical rebuild in section 7 confirms they produce the same output.

## 6. Commands, as run

```bash
# Preprocessing (2026-10-01, on the machine holding the raw CSVs)
python3 prep.py                       # log: logs/prep_original_20261001.log
python3 build.py                      # + PatientID merge

# Tests
python3 src/test_pipeline.py          # 9 checks

# Main experiment  (log: logs/main.log, 12:59:56 -> 13:53:34)
python3 src/run_experiment.py --topk 300 --tag main

# Ablations
./run_ablations.sh                    # self, permlin, k100, k600, rf   (logs/abl_*.log, ablations.log)
./run_final.sh                        # logcn, k20/50/100 mutation sweep (logs/final.log)

# Analysis and outputs
python3 src/analyze.py --tag main
python3 src/mechanism.py
python3 src/make_figures.py
python3 src/analyze_ablations.py
python3 src/make_slides.py
python3 src/check_consistency.py      # 84/84
```

Note on logs: `logs/ablations2.log` and `logs/ablations3.log` are empty. Those two chain scripts
stalled in a polling loop and were killed; their jobs were re-launched unchanged by
`run_final.sh`, whose results are the ones reported. Training logs record fold sizes and timings;
per-gene scores and the chosen ridge penalty are in `results/*_pergene.csv`.

## 7. Verification performed 2026-10-11 (not original results)

1. **Raw files**: SHA-256 computed on the downloading machine — section 2.
2. **Preprocessing rerun**: `prep.py` + `build.py` rerun on the raw CSVs into a scratch folder.
   All six outputs matched the original `data/` files byte-for-byte (identical SHA-256).
3. **Fold reconstruction**: `results/fold_assignments.csv` was written on 2026-10-11 by calling
   the original, deterministic splitters. Its test-fold sizes (lineage-blocked 175/169/170/164/174;
   patient-grouped 171/171/170/170/170) match `logs/main.log` from 2026-10-01 exactly.
4. **Model rerun spot-check**: `--max-genes 40 --arms A_lineage,E_multiomics --tag
   verify_rerun_20261011` (log `logs/verify_rerun_20261011.log`). Across 160 gene × arm × scheme
   rows spanning all three strata, rerun R² and Spearman equal the original values exactly.

Files created by verification are named `*verify_rerun_20261011*`, `fold_assignments.csv` and
`environment.json`. Everything else in `results/` is original.

## 8. Reproducing from scratch

```bash
# 1. Download the six files listed in section 2 from the DepMap portal; check
#    sha256sum against provenance/CHECKSUMS.sha256.
# 2. Put them in ~/mnt/Downloads (or edit D at the top of src/prep/prep.py).
python3 src/prep/prep.py && python3 src/prep/build.py
#    -> writes ~/mnt/data/cbio7215 (edit DST in build.py); copy into ./data/
sha256sum data/*                       # compare with provenance/CHECKSUMS.sha256
# 3. Continue with the commands in section 6.
```

Expected cost on 2 CPU cores: main experiment ~53 min; ablations ~2.5 h (the random forest is
~60 min of that). Results are deterministic: folds are assigned without randomness and every
random step uses seed 0, so a rerun should reproduce the reported values; the 40-gene check
reproduced them exactly.

## 9. Saved predictions and indices

- `results/<tag>_preds_<scheme>_<arm>.npy`: out-of-fold predictions, shape
  852 × (number of targets in that run), rows in cohort order, columns in `<tag>_target_idx.npy`
  order. Saved for arms A and E (the arms the metric analysis needs).
- `results/<tag>_target_idx.npy`: target gene columns of `Y.npy`.
- `results/fold_assignments.csv`: scheme, fold, ModelID, lineage, PatientID, row index.
- `results/<tag>_pergene.csv`: one row per scheme × arm × gene, with R², Spearman, stratum and
  median chosen penalty.
